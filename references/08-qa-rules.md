# 08 · 质量验收规则（L4）

> 不靠"打开 PDF 看一眼"。每一条 P0 都必须有对应的自动检测，检测不到的要显式标为人工，不允许假装覆盖。

## 1. 五层验收

| 层 | 检测对象 | 手段 | 在本系统中的位置 |
| --- | --- | --- | --- |
| Q1 | 数据结构与题目完整性 | 契约校验 | `contract.validate()` → Q1-01 |
| Q2 | 布局几何 | Layout Manifest + PDF 位图墨迹 | P0-02 / P0-02-P / P0-08 |
| Q3 | PDF 文件质量 | pdfinfo / pdffonts / pdftotext | P0-01 / P0-04 / P0-03 |
| Q4 | 视觉质量 | 位图预览 + 人工 | P1-* + `preview/*.png` |
| Q5 | 实物打印 | 打样 + 量测 + 教师试写 | 人工（不自动） |

## 2. P0 阻断规则（未通过即 BLOCK）

| 编号（报告内） | 规则 | 检测方式 | 局限 |
| --- | --- | --- | --- |
| `Q1-01` | 题目数据结构完整、题号唯一、分值自洽 | JSON 契约校验 | 只校验结构，不校验语文知识点对错 |
| `P0-01` | 页面尺寸 210×297mm（±0.5） | `pdfinfo` 实测 | — |
| `P0-02` | 版面块坐标未越界（学生卷/教师卷各一次） | Manifest 校验 | 依赖实测高度准确 |
| `P0-02-P` | PDF 页数 = Manifest 页数 | 两者比对 | — |
| `P0-02-T` | 墨迹未越安全区（12mm，容差 1.2mm） | `pdftoppm` 位图墨迹 | 极浅灰（>240）不算墨迹 |
| `P0-03` | 题干/拼音/文章无丢失 | 逐 Part 可见文本比对 | 不检测字形错乱 |
| `P0-03-T` | 教师卷题干完整 | 结构文本比对 | — |
| `P0-04` | 字体全部嵌入 | `pdffonts` 的 `emb` 全 yes | Type 3 也算嵌入（见 P1-08） |
| `P0-04-T` | 拼音声调字形可提取 | 声调字符逐一核对 | 不能发现"方框替代" |
| `P0-07` | 教师卷未改变学生卷版面 | 页数 + 逐块坐标 + 高度差 ≤0.3mm | — |
| `P0-08` | 版面块无重叠 | Manifest 校验 | 只查块级，不查块内元素（见 P0-12） |
| `P0-08-B` | 无空白页 | 位图墨迹为空 | — |
| `P0-12` | 文字未横向溢出自身容器（容差 0.8mm） | 实测层用 Range 量文字墨迹宽度 | 只测有文本节点的元素；纯图形溢出不计 |
| `P0-09` | 答案与解析未被裁切/丢失 | 教师卷文本比对 | 不校验解析质量 |
| `P0-10` | PDF 可正常打开 | `pdfinfo` 退出码 | — |
| `P0-11` | 学生卷不泄露答案 | 答案串反查学生卷文本 | 只查 ≥3 字且非学生可见文本 |

### 必须人工完成的两条（原规范的 P0-05 / P0-06）

| 规则 | 为什么不能自动 | 人工做法 |
| --- | --- | --- |
| 田字格严重变形 | 位图只能发现越界，量不出格宽与中线位置 | 纸面直尺抽测 3 处，记录 ±0.3mm 内 |
| 答题区不足 | 需要真实笔迹判断"够不够写" | 教师按标准答案实写，记录挤行/出格 |

报告里这两条固定列为"人工待办"，不允许写成 PASS。

## 3. P1 复核规则

| 编号 | 检查 | 触发 |
| --- | --- | --- |
| `P1-06` | 页面底部空白 >45mm（非末页） | 可能是大块整体换页，需判断是否值得拆块 |
| `P1-08` | 字体以 Type 3 嵌入 | 交付印厂前建议归一化 |
| `Q0-W` | 总分与小题合计不一致、大题无题目等 | 数据层问题，需教研确认 |
| 视觉复核 | 模块疏密、同级标题一致、双栏失衡、答题线长短、是否被不合理拆开 | 看 `preview/*.png` |

## 4. 证据包（每次出卷必须留）

```text
build/
├── student.pdf                       # 学生卷
├── teacher.pdf                       # 教师卷（正文页 + 解析页）
├── layout-manifest.json              # 几何真相
├── layout-manifest-teacher.json
├── qa-report.md                      # 人可读验收结论
├── qa-report.json                    # 机器可读，便于 CI 断言
└── preview/*.png                     # 逐页位图
```

CI 断言写法：

```bash
node src/cli.mjs 卷.json --out ./build --quiet || exit 1
node -e 'const r=require("./build/qa-report.json");process.exit(r.verdict==="PASS"?0:1)'
```

CLI 退出码本身已区分语义（`8` = 验收 BLOCK、`4` = 分页失败），大多数 CI 直接用退出码即可。

## 5. 收到 BLOCK 怎么处理

1. 看 `qa-report.md` 的"必须处理"清单，按编号定位规则。
2. 按编号查本文件的"检测方式"列，判断是数据问题、组件问题还是环境问题。
3. 数据问题 → 改题目 JSON；组件问题 → 改 `src/components/*.mjs` / CSS；环境问题 → 查 Chrome 与字体。
4. 修完重跑，**不允许**手工修改 PDF 或跳过某项检测来"通过"。

## 6. 已知盲区（诚实清单）

- 位图检测默认阈值 240，极浅底纹/水印不会被计入墨迹。
- 文本提取无法判断字形是否正确（缺字可能被渲染成空白或方框）。
- 无法自动判断"这道题出得好不好"，只能判断"排得对不对"。
- 无法验证装订边距镜像、出血、专色（当前版本不做印厂级 PDF/X 转换）。
- 跨页的图形题（图片被劈开）无法检测——当前组件集不含图片题。
